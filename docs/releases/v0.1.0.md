# zimg-f64 v0.1.0

This source-first release adds a deliberately isolated implementation of
zimg-phase/geometry-compatible canonical Spline36 evaluated in IEEE-754
binary64.

## Scope

- semantic base: zimg `1ad1895d5ff0bbe69c61243f9996aede713d1b5f`;
- graphengine: `cb5b2ce13384ec2491f0c37256ea210034799f69`;
- binary64 coefficient evaluation, storage, convolution, and inter-axis
  storage;
- generic progressive active-region and chroma-siting derivation;
- format-specific 3840×2160 `yuv422p10le` to 1920×1080 `yuv420p10le`
  reference application;
- deterministic synthetic validation only.

This is not upstream zimg, a bit-exact upstream path, exact-rational
production arithmetic, or a general-purpose converter.

## Validation summary

- unchanged pinned-upstream suite: 162/162 tests passed;
- fork pytest/Hypothesis/SymPy/mpmath suite: 16/16 passed independently with
  MSVC, GCC, and Clang builds;
- MPFR-256/GMP: 8,404 rows and 88,916 coefficients, zero geometry mismatch,
  maximum absolute coefficient error `8.8817841970012523e-16`;
- independent convolution witnesses: 468, maximum absolute error
  `6.821210263296962e-13`, zero non-tie quantization mismatch;
- byte-identical one-thread, 32-thread, and repeated 32-thread outputs across
  MSVC, GCC, and Clang;
- sanitizer/static-analysis gates passed on the public synthetic workload;
- raw FFmpeg framing/decode integration passed.

## Important limitations

- The reference scaler supports only the documented raw format and geometry.
- The original production inputs did not prove chroma location; LEFT was an
  explicit interpretation assumption.
- Binary64 precision does not remove canonical Spline36 ringing.
- Codec, container, timestamp, and delivery-system behavior is downstream.
- No platform binaries are attached to this release.
